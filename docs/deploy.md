# Deploy a judging instance

The [Render Blueprint](../render.yaml) builds the web UI and serves it from the same origin as the API. It runs the background worker in the web service container and uses managed PostgreSQL. The provided Dockerfile installs Poppler and runs the app as a non-root user. A free Render service can sleep, and its free database expires. [Render free-tier limits](https://render.com/docs/free)

1. Create a private bucket with an S3-compatible provider that supports multipart uploads and presigned `PUT` and `GET` URLs. Enter its HTTPS S3 endpoint, signing region, bucket name, and bucket-scoped read/write credentials as `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, and `S3_SECRET_KEY`. The local stack uses SeaweedFS. [S3 multipart upload requirements](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)
2. In Render, create a Blueprint from this GitHub repository. Supply an event join code, a future ISO UTC deadline, and a private organizer login. Share the join code with judges privately. Bootstrapping is idempotent and preserves an existing deadline or organizer account.
3. Add the exact Render app origin to the bucket's browser CORS policy. Allow `PUT`, `GET`, and `HEAD`, allow request headers used for signed uploads, and expose `ETag`. Configure a lifecycle rule to clean up abandoned multipart uploads after one day.
4. Open `/api/healthz` and the in-app Status page. Create a test team, save project details, upload a ZIP with a README, and confirm the accepted receipt and preview. Sign in as organizer and export CSV. Use the resulting service URL in the hackathon submission.

Cloudinary's Upload API has its own chunked upload protocol, and its Free plan limits raw files such as ZIPs to 10 MB. Deadline Crush requires S3 multipart operations and a 100 MiB file limit. [Cloudinary upload protocol](https://cloudinary.com/documentation/upload_images#chunked_asset_upload) · [Cloudinary plan limits](https://cloudinary.com/pricing/compare-plans)
